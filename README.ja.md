# HLS Segment Downloader（Chrome 拡張機能）

[한국어](README.md) | [English](README.en.md) | [简体中文](README.zh-CN.md) | **日本語**

Web ページで再生されている HLS（`.m3u8`）ストリームを自動検出し、セグメントを並列でダウンロードして **1 つの MP4 ファイル**に結合・保存する Chrome/Edge 拡張機能です。映像と音声が別トラックに分かれたストリームも自動で結合します。

UI は韓国語・英語・簡体字中国語・日本語に対応しています（[設定](#設定画面の言語)を参照）。

## インストール（デベロッパーモード）

1. このリポジトリをダウンロード（クローン）します。
2. Chrome で `chrome://extensions` を開き → 右上の**デベロッパーモード**を ON
3. **パッケージ化されていない拡張機能を読み込む** → リポジトリのルートフォルダ（`manifest.json` があるフォルダ）を選択
4. （Edge の場合も `edge://extensions` で同様）

## 使い方

1. 動画のあるページで**動画を再生**します。m3u8 リクエストが検出されると、アイコンに数字のバッジが表示されます。
   - 拡張機能のインストール前から再生していた場合は、ページを再読み込みしてから再生し直してください（インストール前のリクエストは検出できません）。
2. 拡張機能アイコンをクリック → 検出されたストリームの**ダウンロード**をクリック
   - **1 つの動画で m3u8 が 2 つ以上検出されるのは正常です。** プレイヤーはまず**画質一覧（master）**を読み込み、次に選んだ画質の**プレイリスト（media）**を読み込むためです。
   - ポップアップが各項目を確認して `画質一覧 · おすすめ` / `単一プレイリスト` と表示し、画質一覧に含まれるプレイリストは薄く表示して下に移動します。**`おすすめ` の付いた項目をダウンロードしてください。** プレイリストだけをダウンロードすると画質を選べず、音声が別トラックのサイトでは音が入らないことがあります。
   - URL が分かっている場合は、ポップアップの **URL を直接入力**を使用してください。Referer には動画があったページのアドレスを入力するのがおすすめです。
3. 新しいタブで画質 / 音声トラック（複数ある場合）/ ファイル名 / 同時接続数を設定し、**ダウンロード開始**
   - 進行段階：映像のダウンロード →（音声が別の場合）音声のダウンロード → MP4 への変換
4. 完了すると保存先を選ぶダイアログが表示されます。**ダウンロード中はタブを閉じないでください。**

## 設定（画面の言語）

ポップアップ右上の **⚙** ボタン（または `chrome://extensions` → 詳細 → 拡張機能のオプション）で画面の言語を選べます。

- 自動（ブラウザの言語）/ 한국어 / English / 简体中文 / 日本語
- ポップアップと設定画面にはすぐに反映され、すでに開いているダウンロードタブは再読み込みすると反映されます。
- 拡張機能一覧に表示される名前・説明はブラウザの言語に従います（Chrome の仕様）。

## 仕組み

| 段階 | 実装 |
| --- | --- |
| 検出 | `webRequest` でタブのリクエストを監視。URL が `.m3u8` で終わる、またはレスポンスの `Content-Type` が HLS であるリクエストを、その時の **Referer** と一緒に記録 |
| ヘッダーの再現 | CDN の直リンク防止（Referer/Origin のチェック）を通過するため、`declarativeNetRequest` のセッションルールで**ダウンロード用タブからのリクエストに限り** Referer/Origin を元のページの値に設定 |
| 解析 | マスター（画質一覧）/ メディア（セグメント）プレイリスト、`EXT-X-KEY`、`EXT-X-MAP`（fMP4）、`EXT-X-BYTERANGE` に対応 |
| ダウンロード | N 本の並列リクエスト、セグメントごとの指数バックオフによる再試行、順序を保証した書き込み、メモリ使用量の上限（先行取得数を制限） |
| 復号 | `METHOD=AES-128` は WebCrypto（AES-CBC）で自動復号。IV が指定されていない場合は仕様どおりメディアシーケンス番号を使用 |
| 一時保存 | セグメントを RAM ではなく **OPFS（ブラウザ専用のディスク領域）** にトラックごとに追記 → 数 GB の動画でもメモリを圧迫しない |
| MP4 変換 | [Mediabunny](https://github.com/Vanilagy/mediabunny) で**再エンコードせずにコンテナだけを MP4 に変換（remux）**。別トラックの音声はこの段階で映像と結合。画質の劣化がなく高速 |
| 保存 | `chrome.downloads` で保存した後、一時ファイルを削除 |

## 出力形式

常に `.mp4`（H.264/H.265 + AAC など元のコーデックのまま）で保存します。

- 入力セグメント：MPEG-TS、fMP4、packed audio（ADTS `.aac`）に対応
- 映像・音声が分離したストリーム（`EXT-X-MEDIA TYPE=AUDIO`）：選択した音声トラックをダウンロードし、1 つの MP4 に結合
- 万一 MP4 変換に失敗しても、ダウンロード済みのデータは破棄せず元の形式（`.ts`）で保存し、理由を表示します。
- 変換中は元ファイルと MP4 が一時的に同時に存在するため、**動画サイズの約 2 倍のディスク空き容量**が必要です。

## 非対応（意図的なもの / 現在の制限）

- **DRM で保護されたコンテンツ**（Widevine、FairPlay、PlayReady、`SAMPLE-AES`）：検出された場合はダウンロードを拒否します。Netflix や Disney+ などの有料動画配信サービスの多くがこれに該当し、回避する機能は追加しません。
- **ライブストリーム**：ダウンロード時点のプレイリストにある区間のみを保存します（録画機能なし）。
- 広告の挿入などでタイムスタンプが途中でリセットされる（`EXT-X-DISCONTINUITY`）ストリームは、その地点で映像と音声がずれることがあります（警告を表示）。
- Cookie やトークンが短時間で失効するサイトでは、時間のかかるダウンロードの途中で 403 エラーになることがあります。

## 開発

```bash
npm test   # パーサー・ダウンローダー・MP4 変換のユニットテスト（Node 20+、インストールが必要な依存関係なし）
```

```
manifest.json
_locales/              # 拡張機能の名前・説明（en, ko, ja, zh_CN）
src/
  background.js        # m3u8 リクエストの検出（Service Worker）
  popup.html/js        # 検出一覧 UI（master/media を区別）
  options.html/js      # 設定ページ（言語）
  downloader.html/js   # 画質選択・進捗・保存 UI、Referer ルールの設定
  lib/m3u8.js          # プレイリストパーサー
  lib/hls-downloader.js# 並列ダウンロード・再試行・AES-128 復号・順序保証書き込み
  lib/opfs-sink.js     # OPFS 一時ファイル
  lib/remux.js         # TS/fMP4/ADTS → MP4 remux、映像と音声の結合
  lib/i18n.js          # 画面の多言語辞書・言語設定の適用
  lib/classify.js      # 検出したストリームの master/media 関係を判定
  lib/errors.js, format.js
  vendor/mediabunny/   # Mediabunny 1.61.3（MPL-2.0）、バンドルファイルを無改変で同梱
tests/                 # fixtures/ にテスト用の短い TS/AAC ファイル
```
